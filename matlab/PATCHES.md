# Octave compatibility patches to `matlab/formdiscovery1.0/`

These are the only edits made to the original MATLAB sources (item 03 of loop0001).
Every edited line has a `PATCH(octave)` comment, and the original line is kept as a
comment where the change is more than a token swap. `tests/test_patches.py` checks that the
removed/undefined calls are gone from live code, that every file with a marker is listed
here, and that CRLF files kept CRLF line endings (`dijkstra.m`, `dot_to_graph.m` and
`draw_dot.m` use CRLF; the edits keep it).

Target: GNU Octave 10.3.0 (conda-forge, env `fd`). All patched code also stays valid
MATLAB (no Octave-only syntax such as `"..."` escapes, `!`, `#`, or `endif`).

## How the `dot_to_graph` patches were checked

The unpatched file cannot parse any Graphviz 14 layout (patch 14), so the check went in two steps:
1. With only patch 14 applied, run `dot_to_graph` on 4 neato layouts
   (`tests/fixtures/dot_to_graph/lay1..4.dot`: chain6, ring12, directed tree7,
   chain6 + singleton) and 2 hand-written old-format layouts (`old1.dot`: single-line integer
   coordinates with a self-loop and a singleton; `old2.dot`: directed with a C comment). On
   `old1`/`old2` the results matched the completely unpatched file (`isequal`).
2. With patches 10–15 applied, the outputs (`Adj`, labels, `x`, `y`) on all 6 files are
   `isequal` to step 1. This is the committed fixture `tests/fixtures/dot_to_graph.mat`,
   generated by `tests/octave/fx_dot_to_graph.m`.

The multi-line attribute blocks in current Graphviz output (`1 [height=0.5,` / `pos="27,18",`)
still parse because `lst_node` carries over from the line with the `[` to the line with
`pos`. That is luck, not design, and it relies on the original assumption that no label is a
substring of another (ring12 breaks it: `1` is a substring of `10`, `11`, `12`). This quirk is
replicated, not fixed.

## Known Octave warnings (not patched, harmless)

- `vec.m shadows a built-in function`: Octave's builtin `vec(x)` is also `x(:)`.
- `function name 'dijk' does not agree with function filename 'dijkstra.m'`: both MATLAB
  and Octave use the file name, so `dijkstra(...)` works.
- `Matlab-style short-circuit operation performed for operator &` / `|` inside `if`
  conditions (`dot_to_graph.m` and others). Same semantics as MATLAB. Silence it with
  `warning('off', 'Octave:possible-matlab-short-circuit-operator')` if needed.
- `textread`, `strread`, `findstr`, `strmatch`, `nargchk` and `range` all still exist in
  Octave 10.3 (legacy or core); the patches are for MATLAB portability and to remove the
  obsolescence warnings.

## Environment note (not a source patch)

`draw_dot.m` shells out to `neato` found on `PATH`. On this machine `/usr/bin/neato`
(Graphviz 14.1.2) has **no neato layout plugin** ("There is no layout engine support for
"neato""); only `dot` works. The `fd` env's `neato`
(`/home/al/anaconda3/envs/fd/bin/neato`) works, but Octave appends the env's `bin` to the
*end* of `PATH`, so `draw_dot` picks up the broken system binary. Put the `fd` env's `bin`
first on `PATH` (or activate the env) before running any display code. Display is off
(`ps.show*=0`) in all baseline runs.
